# Inception：意图、需求与单元拆分

> 事后整理，原始内容见 [PLAN.md](../PLAN.md) 第 0–4、7 节。

## 意图

**用麻将凑牌代替阳光来种植物的肉鸽塔防**：摸牌 → 凑顺子 / 刻子种植物 → 听牌时赌"胡牌大招" → 关卡之间用小羊跑酷抢牌。单局 4–6 分钟，浏览器直接玩。

出发点：原版塔防的阳光经济是"等数字涨够了就点"，决策很浅；换成麻将后，每一张牌都要在"马上拆了种植物救急"和"留着凑胡牌大招"之间取舍。

## 设计支柱（按优先级取舍）

1. **"听牌"的两难**：拆牌救急 vs. 憋大招，任何设计都不能削弱它。
2. **零学习成本**：不会麻将的人只需要懂"三张连号 / 三张相同"。
3. **张弛节奏**：塔防（紧张）→ 跑酷（放松）→ 三选一（构筑期待）。
4. **短局可重玩**：随机牌山 + 随机强化 + 随机关卡特性。

## 需求

### 功能需求

| 编号 | 需求 | 所属单元 | 状态 |
|---|---|---|---|
| F1 | 牌山：条 / 饼 / 萬 1–9 + 中发白，种子化洗牌，显示剩余张数 | M1 | ✅ |
| F2 | 选 3 张组成面子 → 生成待种植物 → 种到草坪，取代阳光与卡片冷却 | M1 | ✅ |
| F3 | 花色决定植物类型（条攻击、饼防御、萬功能、字牌爆发） | M1 | ✅ |
| F4 | 胡牌判定（2 面子 + 1 雀头 / 4 对子）、听牌提示、番型倍数、全屏伤害 | M1 | ✅ |
| F5 | 改写强化池：去掉阳光类，加入麻将类 | M1 / M3 | 部分 ✅ |
| F6 | 关卡之间的小羊跑酷，捡到的牌成为下一关起手牌 | M2 | 未开始 |
| F7 | 杠 → 植物升星；麻将主题僵尸与 Boss | M3 | 未开始 |

### 非功能需求

- 原生 JS、无构建，`index.html` 直接运行。
- 麻将逻辑与 DOM / canvas 解耦，放在独立文件里，浏览器和 Node 共用，可单元测试。
- 数值集中在 `js/data.js`（番型倍数在 `js/mahjong.js`），方便调参。
- `?seed=` 可复现任意一局。

## 单元拆分（里程碑）

| 单元 | 目标 | 验收方式 |
|---|---|---|
| M0 准备 | 基线快照、本地能跑 | 手动运行 |
| **M1 麻将核心验证** | 只回答一个问题："用麻将凑牌种植物"好不好玩 | 单元测试 + 自动对战机器人 + 真人试玩 Go/No-Go |
| M2 小羊跑酷 | 关卡间的放松段 | 试玩者觉得是"放松"而不是"打断" |
| M3 内容与深度 | 扩展番型、杠升星、麻将僵尸 | — |
| M4 手感与表现 | 胡牌演出、新手引导 | — |
| M5 原创化与上线 | 替换全部原版素材、部署 | 素材清单审查 |

M1 被设为 Go/No-Go 关卡：核心玩法不成立就不进入后续单元。

## 主要风险

| 风险 | 对策 |
|---|---|
| 麻将 + 实时塔防认知负担太重 | M1 先验证；必要时退回"摸牌时游戏减速" |
| 胡牌太难或太容易 | 胡牌条件、手牌上限都做成参数，靠数据调 |
| 素材版权 | M5 全部替换为原创素材，当前仅作学习展示 |
