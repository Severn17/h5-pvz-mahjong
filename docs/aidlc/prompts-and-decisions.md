# 人与 AI 的分工、提示词与关键决策

> 事后整理。M1 开发时的会话记录没有保存，下面的"提示词"根据 PLAN.md、提交记录和当时的反馈整理，**不是逐字原文**；引号内的是记录中保留的原话。

## 分工

| 环节 | AI 负责 | 人负责 |
|---|---|---|
| Inception | 起草玩法设计、"现有代码 → 改造"映射、里程碑与估时、风险表、成功指标 | 提出"麻将代替阳光"的玩法意图；确认设计支柱的优先级；同意把 M1 设为 Go/No-Go 关卡 |
| Construction | 实现 `mahjong.js` 与单元测试；改造主循环与 UI；写自动对战机器人跑数据；根据数据提出调整方案 | 试玩并给出体感反馈；要求做 Review；决定采纳哪个调整方案 |
| Operations | 配置 CI、整理仓库与 AI-DLC 文档、发布到 GitHub | 决定展示方式（独立公开仓库、保留原作者历史）；最终审核 |

核心原则：**AI 出方案和数据，人做判断**。每次调整都先有数据或试玩反馈，再改数值。

## 关键提示词（据记录整理）

### Inception

1. **给出意图，让 AI 出完整计划**：在现有肉鸽版塔防上，用麻将凑牌代替阳光来种植物，关卡之间加小羊跑酷，出一份执行计划。
   → 产出 [PLAN.md](../PLAN.md)：设计支柱、牌与植物的映射表、番型表、逐文件改造映射、M0–M5 里程碑、风险表。
2. **收窄范围**：先只做 M1，回答"用麻将凑牌种植物好不好玩"，不做跑酷和美术。
   → M1 被定义为 Go/No-Go 关卡，验收标准写进计划。

### Construction

1. **先写纯逻辑和测试**：`mahjong.js` 不碰 DOM / canvas，浏览器和 Node 共用，用 `node --test` 覆盖胡牌、听牌、番型。
   → `8e3a830`，逻辑、测试和界面接入在同一个提交里完成。
2. **用机器人代替手玩调数值**：让 AI 写贪心 / 憋胡两种策略的自动对战，各跑 10 局统计胜率、面子数、时长。
   → 发现纯随机凑面子太慢，加入"天降好牌"。
3. **体感反馈**："打牌出植物难度有点高。"
   → AI 把它拆成"看不出能组什么"和"开局太难"两个问题分别处理（`716b181`）。
4. **要求 Review 节奏**：按关统计打牌频率、每关时长、胡牌次数。
   → 发现"操作太密""憋胡被惩罚""后期没压力"三个问题（`871f748`）。

### Operations

1. "我想要把这个项目提交到github" → 发现原 remote 是原作者仓库、本地是浅克隆，补全历史后推送。
2. "这个相当于是fork别的项目，然后我这个项目是作为给 aws aidle的学习展示项目的。你想想怎么规划提交这个仓库呢？" → 产出本目录、署名与版权声明、标签、CI 的方案。
3. 决定删掉已推送的仓库，本地整理完再重新公开发布。

## 关键决策与纠偏

| 时间 | 决策 / 纠偏 | 触发 | 结果 |
|---|---|---|---|
| 2026-09-18 | M1 设为 Go/No-Go 关卡，先不做跑酷和美术 | 规划时识别出"认知负担"是最大风险 | 范围收窄到一个可验证的问题 |
| 2026-09-18 | 天降牌加入"好牌"机制（80%） | 机器人数据：纯随机凑面子太慢，6 局全部倒在第 2 关 | 面子数翻倍 |
| 2026-09-18 | 向日葵直接掉牌，不做"加速摸牌" | 实现时发现复用产阳光逻辑更直观 | 玩家能直接看到收益 |
| 2026-09-18 | 手牌区移到底部托盘并放大 | 操作区位置与大小（提交未记录具体原因） | `871736c` |
| 2026-09-18 | 降低凑牌门槛：提示、一键选面子、第 1 关不放萬、赠送植物；好牌 80% → 50% | 反馈"打牌出植物难度有点高" | 两种策略胜率都到 9/10 |
| 2026-09-18 | **纠偏**：去掉"2 秒内胡牌"的自摸加成，改为胡牌储备 + 大波加成 | Review 发现之前的设计在惩罚"憋胡"，违背设计支柱 1 | 每局胡牌 0.7 → 1.3–1.8 次 |
| 2026-09-18 | **纠偏**：摸牌从"快而随机"改为"少而精" | 数据显示游戏在逼玩家刷牌（35 次/分） | 打牌频率降到 5–11 次/分 |
| 2026-09-28 | 以独立公开仓库发布，保留原作者完整历史，美术素材声明不可商用 | 作为学习展示项目公开 | 本仓库 |

## 经验

- **机器人数据比手感更早暴露问题**：好牌机制、节奏问题都是先在统计里看到的。
- **AI 自己的设计也需要被 Review**：M1-1 试做时加入的"2 秒自摸"，在第三轮 Review 时被发现和设计支柱冲突，随后推翻。
- **把模糊反馈拆成具体问题**："太难"被拆成"看不出来"和"开局太难"，各自对症处理，而不是笼统地调低难度。
